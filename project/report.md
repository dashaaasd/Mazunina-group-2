## 1. Паспорт проекта

- **Название проекта:** Сервис предсказания эффективности рекламных кампаний
- **Автор:** Мазунина Дарья Андреевна
- **Группа:** БСБО-51-24

Проект представляет собой ML-сервис для прогнозирования ROAS (Return on Ad Spend) рекламных кампаний и рекомендации наиболее эффективных рекламных каналов. Сервис на основе исторических данных о кампаниях предсказывает окупаемость вложений в рекламу и помогает выбрать оптимальную платформу для размещения. Результат — REST API на FastAPI с двумя эндпоинтами.

## 2. Постановка задачи и контекст

1. **Предметная область и задача:**
   - Задача: регрессия — прогнозирование числового значения ROAS по параметрам рекламной кампании.
   - Пользователь: маркетолог, планирующий рекламную кампанию. Сценарий использования:
      1. Пользователь вводит параметры планируемой кампании (платформа, бюджет, цель, устройство, дата)
      2. Сервис прогнозирует ROAS — сколько рублей выручки принесёт каждый рубль затрат
      3. Сервис рекомендует лучший канал для максимизации окупаемости

2. **Формулировка задачи в терминах ML/ИИ:**
   - Входные данные: метрики (CTR, bounce_rate, conversions, ad_spend, quality_score), категориальные (platform, campaign_objective, device_type, operating_system, ad_placement, day_of_week), временные (month, quarter, hour_of_day, is_weekend)
   - Целевая переменная: ROAS (Return on Ad Spend)
   - Требования: предсказание в реальном времени (<1 сек), интерпретируемость (feature importance), устойчивость к временному дрейфу данных

3. **Целевые метрики качества:**

| Метрика | Обоснование |
|---------|-------------|
| **R²** | Основная — измеряет долю объяснённой дисперсии, стандарт для регрессии |
| **MAE** | Средняя абсолютная ошибка в единицах ROAS — интерпретируема для бизнеса |
| **RMSE** | Штрафует большие ошибки сильнее — важно для высоких ROAS |
| **MAPE** | Процентная ошибка — позволяет сравнивать точность на разных масштабах |

## 3. Данные

1. **Источник данных:**
   **Датасет:** Digital Advertising Campaign Performance Dataset ([Kaggle](https://www.kaggle.com/datasets/manishabhatt22/marketing-campaign-performance-dataset)). 10 000 записей о рекламных кампаниях за 2024–2026 годы. Данные синтезированы, но при этом содержат реалистичные бизнес-закономерности.

2. **Структура данных:**

| Группа признаков | Примеры | Тип |
|------------------|---------|-----|
| Метрики эффективности | CTR, bounce_rate, conversions, quality_score, actual_cpc | Числовые |
| Расходы | ad_spend | Числовые |
| Каналы | platform (6 значений), ad_placement (6 значений) | Категориальные |
| Контекст | device_type (3), operating_system (5), campaign_objective (5) | Категориальные |
| Временные | start_date, quarter, day_of_week, hour_of_day, campaign_day | Дата/числовые |

3. **Предобработка и EDA:**
   **Ключевые шаги (`preprocessor.py`):**
   - Удаление утечек: `revenue`, `profit` (ROAS = revenue / ad_spend)
   - Извлечение временных признаков из `start_date`: `year`, `month`, `week_of_year`, `is_weekend`
   - Кодирование категорий: LabelEncoder для 19 категориальных признаков
   - Масштабирование числовых признаков: StandardScaler
   - Заполнение пропусков медианами

   **Важные наблюдения EDA (`notebooks/01_eda_v2.ipynb`):**
   - ROAS имеет сильный скос вправо (среднее 7.52, максимум 487) — есть редкие «звёздные» кампании
   - **LinkedIn лидирует по ROAS** (7.5x), но Facebook/Instagram дают больший абсолютный profit
   - **Desktop стабильно эффективнее Mobile** на ~30%
   - **Сезонность:** ROAS колеблется по месяцам от 6.3 до 8.9x (разница ~40%)
   - Позитивные корреляции: conversions (+0.30), CTR (+0.25), pages_per_session (+0.28)
   - Негативные корреляции: bounce_rate (−0.34), actual_cpc (−0.24)
   - **Бюджет сам по себе не гарантирует результат:** ad_spend (−0.04) — почти не коррелирует с ROAS

## 4. Модели и подходы

1. **Базовые (baseline) модели (`notebooks/02_baseline_models.ipynb`):**

Сравнили 7 моделей на временном сплите 70/15/15 с `R²` на валидации:

| Модель | Val R² | Val MAE | Вывод |
|--------|--------|---------|-------|
| Linear Regression | 0.427 | 4.69 | Не улавливает нелинейности |
| Ridge (L2) | 0.427 | 4.69 | Аналогично Linear Regression |
| Lasso (L1) | 0.434 | 4.65 | Отбор признаков не дал улучшений |
| Decision Tree | 0.732 | 2.48 | Сильное переобучение (Gap ~0.9) |
| Random Forest | 0.840 | 1.86 | Хорошая устойчивость |
| Gradient Boosting | 0.876 | 1.78 | Отличный результат |
| **CatBoost** | **0.882** | **1.77** | **Лучший R², минимальный Gap** |

2. **Улучшенные модели и эксперименты (`notebooks/03_hyperparameter_tuning.ipynb`):**
   - **Метод:** RandomizedSearchCV с TimeSeriesSplit (5 фолдов), 50 итераций, 7 параметров.
   - **Лучшие параметры (CV R² = 0.814):** `depth=8`, `lr=0.05`, `iterations=700`, `l2_leaf_reg=5`, `bagging_temperature=0`, `border_count=128`.
   - **Результат на фиксированной валидации:** `Val R² = 0.879`.

3. **Вывод по моделям:**
   - **CatBoost** показал лучший баланс точности (`R² 0.882`).
   - **Подбор гиперпараметров не дал значимого прироста**, что подтверждает удачный выбор параметров в baseline (`depth=6`, `lr=0.05`).
   - **Линейные модели не справляются** с задачей — данные содержат сложные нелинейные зависимости.

## 5. Экспериментальный протокол и результаты

1. **Экспериментальный протокол:**
   - **Split:** Временной (без перемешивания!): Train 70% (2024-01-01 – 2025-06-14), Validation 15% (2025-06-14 – 2025-10-07), Test 15% (2025-10-07 – 2026-01-30). Имитирует реальный сценарий прогнозирования в будущее.
   - **Метрики:** `R²` (основной), `MAE`, `RMSE`, `MAPE`.
   - **Подбор гиперпараметров:** RandomizedSearchCV с TimeSeriesSplit (5 фолдов).

2. **Сравнение моделей по метрикам:**

| Модель | Val R² | Val MAE | Вывод |
|--------|--------|---------|-------|
| Linear Regression | 0.427 | 4.69 | Не улавливает нелинейности |
| Ridge (L2) | 0.427 | 4.69 | Аналогично Linear Regression |
| Lasso (L1) | 0.434 | 4.65 | Отбор признаков не дал улучшений |
| Decision Tree | 0.732 | 2.48 | Сильное переобучение (Gap ~0.9) |
| Random Forest | 0.840 | 1.86 | Хорошая устойчивость |
| Gradient Boosting | 0.876 | 1.78 | Отличный результат |
| **CatBoost** | **0.882** | **1.77** | **Лучший R², минимальный Gap** |

**Итоговые результаты на отложенной тестовой выборке (Final Test):**

| Модель | Test R² | Test MAE | Test RMSE | MAPE (Test) |
|--------|---------|----------|-----------|-------------|
| **CatBoost (Baseline)** | **0.8305** | **2.5578** | **6.043** | **37.4%** |

> **Интерпретация:** Модель объясняет **83%** вариации ROAS на новых, невидимых ранее данных. Средняя ошибка прогноза составляет ~2.56 пунктов ROAS, что является хорошим результатом для данных с сильным разбросом (среднее ROAS = 7.5, std = 15.0).

3. **Выбор финальной модели:**

Финальной моделью выбран **CatBoost с параметрами Baseline**: `iterations=500`, `learning_rate=0.05`, `depth=6`.

**Обоснование:**

   1. **Лучшая точность на валидации** (0.882 против 0.879 у tuned-версии).
   2. **Меньший разрыв между Train и Val** (0.07 против 0.09) — лучшая обобщающая способность.
   3. **Быстрее обучается** (остановилась на 497 итерациях против 700 у tuned).
   4. **Baseline-параметры оказались близки к оптимальным** для данного датасета.

## 6. Архитектура решения и сервис

1. **Архитектура пайплайна:**
   1. **`src.train`** → загружает конфиг, данные → вызывает `CampaignDataProcessor` для предобработки → обучает `CatBoostRegressor` → сохраняет модель и препроцессор.
   2. **`src.api.app`** → при запуске загружает модель и препроцессор через `ROASPredictor` → обрабатывает входящие запросы.
   3. **`src.models.predictor.ROASPredictor`** — класс-адаптер:
      - `predict_single()`: предобработка запроса через загруженный `CampaignDataProcessor`, предсказание.
      - `recommend_channel()`: прогоняет запрос по всем платформам, возвращает лучшую.

2. **API и endpoints:**
   - **`POST /predict`**:
     - *Input:* `CampaignRequest` (Pydantic-схема, обязательны `platform`, `ad_spend`, `start_date` и 4 категориальных поля).
     - *Output:* `{"predicted_ROAS": float, "status": "success"}`.
   - **`POST /recommend`**:
     - *Input:* `RecommendRequest` (Pydantic-схема, **без поля `platform`** — он перебирается автоматически).
     - *Output:* `{"best_channel": str, "best_ROAS": float, "all_results": list}`.
   - **`GET /health`**: возвращает статус сервиса и признак загрузки модели.

3. **Технологический стек:**
   - **API:** FastAPI, Uvicorn, Pydantic
   - **ML:** CatBoost, scikit-learn, pandas, numpy
   - **Эксперименты:** MLflow, Jupyter
   - **Контейнеризация:** Docker
   - **Конфигурация:** YAML (модель) + `.env` (секреты — не используются)
   - **Тестирование:** pytest

## 7. Наблюдаемость, конфигурация и безопасность

- **Логи:** Используется стандартный модуль `logging` с уровнями INFO/WARNING/ERROR. Каждый запрос к `/predict` и `/recommend` логируется с IP-адресом клиента, входными параметрами и результатом. Ошибки обработки записываются через `logger.exception()` с полным traceback. Эндпоинт `/health` возвращает статус `"healthy"` / `"degraded"` в зависимости от состояния модели.
- **Конфигурация:** Параметры модели (`iterations`, `depth`, `lr`) вынесены в `configs/model_config.yaml`. Пути к данным и артефактам — там же. Шаблон `.env.example` для будущих секретов.
- **Безопасность:** Секретов нет. Данные локальные. При развёртывании в облаке необходимо использовать переменные окружения для чувствительных параметров.

## 8. Ограничения и дальнейшая работа

**Ограничения:**

- **Синтетические данные** — модель обучена на сгенерированном датасете с искусственными бизнес-правилами. Перед использованием в продакшне необходима валидация на реальных данных рекламных кампаний.
- **Временной горизонт** — данные охватывают 2024–2026 годы; при изменении рыночных паттернов требуется переобучение.
- **Высокий MAPE (37.4%)** — модель хуже работает на кампаниях с очень высоким ROAS (выбросы). Логарифмирование целевой переменной могло бы снизить этот показатель.
- **Ограниченный набор платформ** — 6 рекламных платформ; добавление новых требует дообучения с их данными.
- **Нет мониторинга дрейфа** — в текущей версии отсутствует автоматическое отслеживание деградации качества модели в продакшне.

**Что можно улучшить:**

- **Модель:** логарифмирование ROAS перед обучением для снижения MAPE; feature selection для удаления коррелирующих признаков; добавление доверительных интервалов к предсказаниям.
- **Сервис:** кэширование предсказаний для часто повторяющихся запросов; асинхронные батчевые предсказания; добавление метрик в формате Prometheus для мониторинга.
- **Данные и эксперименты:** автоматическое переобучение по расписанию; расширение датасета новыми платформами и отраслями.

## 9. Сценарий демонстрации на защите

**Запускаем сервис:**

```bash
cd project
source .venv/bin/activate
uvicorn src.api.app:app --reload --port 8000
```

Или через Docker:
```bash
cd project
docker build -t roas-service .
docker run -p 8000:8000 roas-service
```

**Сценарий 1 — Прогноз ROAS для конкретной кампании (`/predict`):**

Открываем Swagger UI: http://localhost:8000/docs → `POST /predict` → вводим параметры Facebook-кампании с бюджетом $5000 → получаем `predicted_ROAS`. Меняем платформу на LinkedIn — показываем, что ROAS меняется.

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8000/predict" -Method Post `
  -ContentType "application/json" `
  -Body '{"platform":"Facebook","campaign_objective":"Conversions","device_type":"Desktop","operating_system":"Windows","ad_placement":"feed","day_of_week":"Monday","ad_spend":5000,"start_date":"2025-01-15"}'
```

**Сценарий 2 — Рекомендация лучшего канала (`/recommend`):**

Тот же запрос, но без поля `platform`. Сервис перебирает все 6 платформ и возвращает ранжированный список с рекомендацией.

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8000/recommend" -Method Post `
  -ContentType "application/json" `
  -Body '{"campaign_objective":"Conversions","device_type":"Desktop","operating_system":"Windows","ad_placement":"feed","day_of_week":"Monday","ad_spend":5000,"start_date":"2025-01-15"}'
```

**На что обратить внимание:**

- `/health` показывает статус загрузки модели — наблюдаемость работает.
- Логи в терминале при каждом запросе — видно IP, параметры, результат.
- Ноутбук `02_baseline_models.ipynb` — таблица со сравнением 7 моделей, обоснование выбора CatBoost.
- Ноутбук `01_eda_v2.ipynb` — графики сезонности, feature importance, распределение ROAS.
- `configs/model_config.yaml` — все гиперпараметры вынесены из кода.
- Модель обучается автоматически при первом запуске, если нет артефактов.
